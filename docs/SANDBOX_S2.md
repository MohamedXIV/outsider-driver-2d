# Sandbox S2 — Device Knowledge & Earned Local-Language Markers

**Design contract:** a taxi sandbox in which knowledge belongs to the persistent player/world state, not an authored passenger scene, UI flag or language model.

## Playable S2 rules

1. The initial sandbox HUD offers exactly one one-time starter choice: **GPS / Translator / Radio**. The choice is persistent for a given world/seed; New Seed resets the choice. The devices are distinct **knowledge affordances**, not three equivalent buffs.
2. **GPS** grants `map:district-graph` and shows graph-hop information about a selected systemic offer. It does not decode alien words or grant free routes.
3. **Translator** grants `tool:local-phrase-scanner` only. The first time a live, locally present speaker responds to `intent:ask_destination`, the device records `lexicon:local:route-marker` with the real offer ID as event provenance. The CURRENT frame still shows the unknown local phrase; subsequent conversations recognize only the **route marker and named destination**, not the rest of the utterance, motives, or complete dialect. A second, unrelated local-speaking NPC can use the same acquired marker; their trip demand remains generated by the population system.
4. **Radio** grants `radio:alien-signal-pattern`, displaying a garbled local broadcast snippet. It does not silently translate the signal, tune to human stations or require generated alien-language LLM content.
5. All knowledge changes are recorded exactly once in the canonical `SandboxWorld.events` ledger. Direct attempts to learn with another device, from an expired/unreachable/invalid offer, or from an already-known fact do nothing.
6. `SandboxConversation` injects a **snapshot** of `understands_speaker` and `knows_local_route` into the same compiled **reusable Ink policy**; Ink only selects authored response lines. Only the world can record learning and validate accepted/declined jobs.
7. `SandboxWorld` snapshot schema is v2; `SandboxSave` envelope is v3 (`user://outsider_driver_sandbox_v3.json`). New saves keep knowledge, device, full offers, NPC state and current Ink frame; older experimental save migration is deliberately not undertaken.

## Tests and scope limits

- `tests/test_sandbox_knowledge.gd` proves unique device facts, one-time choice, observation gating, two local NPC contexts, before/after contextual Ink, save/restore, repeat-learning idempotency, cross-seed replay, and invalid save-state rejection.
- `tests/test_sandbox_scene.gd` and `tests/web_sandbox_smoke.cjs` perform actual device click and a real local Ink query with **initial incomprehension → observed marker → new conversation with bounded partial recognition**, plus mid-choice world/Ink save-reload and once-only fare.
- Existing S1 trade/local speech and old P1/P2 regression tests remain separate.
- S2 is **not** a grammar parser, deep lexicon progression, universal Translator, NPC AI conversation model, radio simulation, emergent gossip, or completed social/economic city. The two available languages in this small test city are illustrative; no live human station or illegal antenna mechanic yet.
- Windows *export* alone does not constitute a Windows-runtime or human-acceptance pass. The temporary schematic HUD is not the intended final illustrative/isometric street gameplay.

Next steps should deepen autonomous NPC/social state, world economics and real taxi travel without turning the initial sandbox proof into another scripted passenger slice.
